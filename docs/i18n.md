# Traducción (es / pt-BR)

## Uso

- Banderas 🇦🇷 / 🇧🇷 en header (desktop), header mobile y login/registro.
- La elección se guarda en la cookie `SERVIDO_LOCALE` (`es` o `pt-BR`).

## Archivos

- `messages/es.json` y `messages/pt-BR.json` — UI principal y `apiErrors`
- `messages/adminDashboard.es.json` / `.pt-BR.json` — panel admin (merge en `i18n/request.ts`)
- `messages/emails.es.json` / `emails.pt-BR.json` — plantillas de email
- `messages/legal/*` — términos, privacidad, careers
- `lib/i18n/translate-client-error.ts` — errores de API (español del servidor → claves `apiErrors`)
- `lib/i18n/resolve-app-notification.ts` — notificaciones in-app (`appNotifications`)
- `i18n/config.ts`, `i18n/request.ts`, `components/layout/locale-flag-toggle.tsx`

## Migrar una pantalla

1. En el componente cliente: `import { useTranslations } from "next-intl"`
2. `const t = useTranslations("nombreSeccion")`
3. Reemplazar strings: `t("clave")` con parámetros `{ name: "..." }` si hace falta
4. Agregar la misma clave en **ambos** JSON (o en los JSON de admin/legal/emails según corresponda)
5. Errores de API en UI: `describeApiError(err, useTranslations("apiErrors"), fallback)`

## Estado (oleadas)

| Área | Estado |
|------|--------|
| Comprador (carrito, checkout, dashboard) | Hecho |
| Vendedor, restaurante, cadete | Hecho |
| Público (catálogo, servicios, reservas) | Hecho |
| Emails, notificaciones in-app, `apiErrors` checkout | Hecho |
| Admin (`adminDashboard`, broadcast, precios suscripción) | Hecho |

## Pendiente opcional

- Metadata SEO global en `app/layout.tsx` por locale
- APIs secundarias (geocoding, etc.) donde el usuario vea el `error` crudo
- Contenido generado por usuarios (productos, broadcasts) — no se traduce automáticamente
